# SYSLight — Typography & Design System Audit
### Principal Designer Review · Enterprise Grade · July 2026

---

## 1. Executive Summary

**Project**: SYSLight by Systems Creator — Premium Architectural LED Lighting  
**Stack**: Next.js 16 · React 19 · Tailwind CSS v4 · GSAP · Three.js · Framer Motion  
**Styling**: Tailwind v4 utility classes with `@theme` design tokens in `globals.css`  
**Font System**: Three switchable typographic themes (Default · Azo · Editorial) — a rare and sophisticated UX feature  
**Pages**: Home, Products Hub, Product Category, Product Detail, Smart Lights, About, Projects, Contact

**Overall Assessment**: The codebase is a **premium luxury product site** with a strong, coherent aesthetic identity. The design is sophisticated — dark/light mode, font theme switching, scroll animations, and 3D WebGL are all implemented. However, the typography has grown organically and now contains **47+ distinct, one-off font-size values** across files, creating invisible inconsistencies at scale. No unified typography scale exists in the CSS layer. All sizing is Tailwind utility-based with arbitrary pixel values scattered throughout components.

**Critical Finding**: The site uses `text-xs` (12px) as its **primary body copy size** across almost every page. For a luxury product aimed at architects and designers reading detailed specifications, this creates significant readability and accessibility concerns — particularly in forms, product descriptions, and specifications tables.

## 3. Readability Audit

### 3.1 Body Copy — Critical Issue

**Finding**: The site uses `text-xs` (12px) as the **primary body copy size** for ALL descriptive text, product descriptions, form labels, and specification paragraphs. This applies to:

- Product description on ProductDetail page (`font-sans text-xs md:text-sm`)
- All section description paragraphs on every page
- Contact form field labels
- Testimonial quotes
- Footer link text
- Sidebar filter labels

**Impact**: At 12px on body text, readability suffers significantly for:
- Users with moderate visual impairment
- Users zoomed out on large monitors
- Mobile users in non-ideal lighting

**WCAG Requirement**: WCAG 2.2 Success Criterion 1.4.4 requires text to be readable at 200% zoom. While 12px technically passes at 200% zoom, it fails the spirit of 1.4.10 (Reflow) at small sizes.

**Recommendation**: Minimum 14px (text-sm) for body copy, 13px for secondary/supporting text.

### 3.2 Minimum Sizes — Accessibility Failures

| Size | Location | Issue | WCAG |
|------|----------|-------|------|
| 8px | `text-[8px]` — "active" font badge, pillar labels | Far below minimum | ❌ Fail |
| 8px | ProductCard bestseller badge | Below minimum | ❌ Fail |
| 9px | All overlines, dropdown headers, sidebar labels | Below minimum | ⚠️ Borderline |
| 10px | Breadcrumbs, most mono labels | Below 11px guideline | ⚠️ Borderline |

**Guideline**: WCAG 2.2 and APCA (Advanced Perceptual Contrast Algorithm) recommend 11px as an absolute minimum for UI labels. Apple HIG: 11pt minimum (≈15px on 96dpi displays). Google Material: 10sp minimum for captions.

**Recommendation**: 
- Minimum label/overline size: **11px**
- Minimum caption/meta size: **12px**
- Minimum body copy: **14px**

### 3.3 Line Width (Measure)

Most content uses `max-w-xl` (576px), `max-w-2xl`, `max-w-4xl`, `max-w-5xl` for container widths. The actual paragraph width is constrained well (typically `max-w-lg` to `max-w-xl`). This is **good practice** — optimal reading measure is 45–75 characters (roughly 400–600px at 16px). No issues found here.

### 3.4 Contrast Issues

**Color tokens analyzed**:
- `--color-text-dim: #4B4B5E` on `--color-void: #FFFFFF` → ratio: ~7.1:1 ✅ AA Pass
- `--color-text-ghost: #8E8D9F` on `--color-void: #FFFFFF` → ratio: ~2.5:1 ❌ Fail (used widely for metadata)
- `--color-text-dim: #9B99BB` on dark `--color-void: #010101` → ratio: ~5.2:1 ✅ AA Pass
- `--color-text-ghost: #5D5B7C` on dark `--color-void: #010101` → ratio: ~2.3:1 ❌ Fail

**Ghost text** (`text-text-ghost`) is used extensively for sub-labels and metadata but **fails WCAG 4.5:1 minimum** in both light and dark modes. This is currently applied to:
- Dropdown category group headers
- "Scroll down" cue
- Font menu font descriptions
- File upload size hint text
- Contact form encryption label
- Table "Test Chamber" labels

| Issue | Location | Severity | WCAG Criterion |

| Missing `aria-label` on icon-only buttons | Navbar theme/font toggle | 🟡 Medium | 4.1.2 |
| `aria-label` present ✅ | Carousel prev/next buttons | ✅ Pass | 4.1.2 |

| `focus:outline-none` without replacement | Button component | 🟡 Medium | 2.4.11 |
| Button min target size | 8×8 "active" badge in font menu | 🟡 Medium | 2.5.8 (AA New) |
| Minimum 24×24 target | Close/chevron buttons in sidebar | 🟡 Medium | 2.5.8 |
| Semantic heading hierarchy | h4 used in tables without h1→h4 chain | 🟡 Medium | 1.3.1 |
| `lang="en"` present ✅ | Root HTML | ✅ Pass | 3.1.1 |
| `aria-expanded` on accordions ✅ | ProductSpecifications | ✅ Pass | 4.1.2 |
| Reduced motion respected ✅ | TestimonialsCarousel | ✅ Pass | 2.3.3 |

### 4.2 Focus States

The `Button` component uses `focus:ring-1 focus:ring-gold/50`. This is a valid focus indicator, but:
- Semi-transparent focus rings (`/50` opacity) may not meet the 3:1 contrast requirement for focus indicators (WCAG 2.4.11, new in WCAG 2.2)
- The navbar theme/font toggle buttons have `focus:outline-none` with **no replacement focus style**

### 4.3 Contrast Ratio Summary

| Pair | Ratio | WCAG AA | Notes |
|------|-------|---------|-------|
| `#010101` / `#FFFFFF` | 21:1 | ✅ AAA | Primary text on white/dark |
| `#4B4B5E` / `#FFFFFF` | 7.1:1 | ✅ AAA | `text-dim` on light |
| `#8E8D9F` / `#FFFFFF` | 2.5:1 | ❌ Fail | `text-ghost` on light |
| `#6A67CC` / `#010101` | 7.8:1 | ✅ AAA | Gold on dark |
| `#6A67CC` / `#0D0C15` | 7.5:1 | ✅ AAA | Gold on dark surface |
| `#9B99BB` / `#010101` | 5.2:1 | ✅ AA | `text-dim` on dark |
| `#5D5B7C` / `#010101` | 2.3:1 | ❌ Fail | `text-ghost` on dark |
| `#6A67CC` / `#FFFFFF` | 3.1:1 | ❌ Fail (normal) | Gold on light (< 4.5:1) |

**Critical**: The brand color `--color-gold` (#4D4A9D in light mode) **fails contrast on white backgrounds** at 3.1:1. It only passes Large Text (3:1 threshold). Since gold is used for interactive labels like breadcrumb current page, dropdown headers, and overline text, this is an accessibility concern.

## 6. Design System Specification

### 6.1 Design Principles

1. **Luxury hierarchy first** — serif headings command attention; sans serves function; mono signals precision
2. **Readable at every level** — no text below 11px in any production context
3. **Purposeful contrast** — ghost text reserved for truly decorative metadata only
4. **Consistent rhythm** — 4px base grid, 8pt spacing multiples
5. **Dual personality** — light mode: clean editorial; dark mode: immersive jewel-box

### 6.2 Semantic Color Usage (Corrected)

| Token | Light | Dark | Use |
|-------|-------|------|-----|
| `--color-void` | #FFFFFF | #010101 | Page background |
| `--color-surface` | #FFFFFF | #0D0C15 | Card, nav background |
| `--color-surface-alt` | #F5F5F7 | #141321 | Subtle elevated surface |
| `--color-cream` (→ rename `--color-ink`) | #010101 | #E5E5E6 | Primary text |
| `--color-text-dim` | #4B4B5E | #9B99BB | Secondary text |
| `--color-text-ghost` | #8E8D9F → **raise to #767589** | #5D5B7C → **raise to #7D7B9B** | Decorative metadata ONLY |
| `--color-gold` | #4D4A9D | #6A67CC | Brand accent, interactive |
| `--color-gold-light` | #6C69C1 | #8F8DF0 | Hover state for gold |
| `--color-gold-muted` | #333175 | #413F8C | Subtle gold tint |
| `--color-border` | #E5E5E6 | #201F33 | Separator, card border |
| `--color-border-mid` | #CCCCCC | #2E2D4A | Stronger separator |

**Note**: `--color-text-ghost` must be raised to at least 4.5:1 contrast ratio against backgrounds before use on any readable text. Otherwise it must be used only for decorative, non-essential visual elements.

## 9. Font Recommendations

### Current Stack — Keep (Excellent)

**Default Theme** (Cormorant Garamond + DM Sans + Space Mono) is a sophisticated, well-paired luxury stack.  
- Cormorant Garamond: exquisite for display and headings. The light weight (300) is the signature.  
- DM Sans: clean, modern, optical sizing (9–40) means it renders beautifully at all sizes.  
- Space Mono: perfect technical precision — exactly right for spec labels and product codes.

### Optimization Recommendation

**Reduce Google Fonts import** — currently loading 6 families in one call. Only Default theme needs to load eagerly:

```css
/* Eager load — Default theme (always needed) */
```

## 15. Final Recommendations

### For the Design

1. **Keep the triple-font-theme system** — it's genuinely innovative for a product site and enhances the premium feel. Consider adding a brief animation when themes switch.

2. **The serif/sans/mono trinity is your design language** — protect it. Cormorant for emotion, DM Sans for clarity, Space Mono for precision. Never mix these intentionally.

3. **Establish a minimum text size policy**: 11px floor for any visible text, no exceptions. Visual design must not override functional accessibility.

4. **Reconsider the ghost text usage** — currently `text-ghost` is used for readable content (form file hints, descriptions). Raise the token value or stop using it for readable content.

5. **Regularize the "border-radius inconsistency"** — the site mixes `rounded-[1px]`, `rounded-[2px]`, `rounded-[4px]`, `rounded-2xl` (16px), and `rounded-full`. The new components use `rounded-2xl` while older components use `rounded-[1px]`. Decide: is the brand sharp-edged or soft-edged? Both work, but they need to coexist intentionally.

### For the Engineering

6. **Introduce Tailwind `@layer utilities` typography helpers** in `globals.css` — classes like `.type-overline`, `.type-body`, `.type-label` that apply consistent font, size, tracking, and weight in one class. This prevents future divergence.

7. **The responsive body size pattern `text-xs md:text-sm`** (12px → 14px) used in many places is correct thinking — just move the base value up: use `text-sm md:text-base` (14px → 16px) for important descriptive text.

8. **Consolidate tracking values** from 12 arbitrary values to 4 semantic tokens. This is the highest-leverage consistency fix in the entire codebase.

9. **Consider loading Editorial theme fonts lazily** — currently all 6 Google Font families load on every page. Only the Default theme fonts need to load eagerly.

10. **The design is fundamentally strong** — Azo Sans addition is excellent, the new ControlModes and SmartSolutions components are beautifully designed. These updates refine a strong foundation rather than rebuild it.
